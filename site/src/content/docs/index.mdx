The **Agentic Workflow Protocol (AWP)** is an open specification for portable, auditable and policy-controlled agentic workflows. A workflow is described in a declarative manifest: which agents and tools take part, which steps run in which order, within which limits, under which governance rules, and which audit events it leaves behind.

AWP is a **specification, not a platform**. A *runtime* reads a manifest, validates it, enforces its limits and governance rules while executing it, and emits audit events with standardized semantics. Any runtime may implement AWP; [OpenAgentix](/implementations/openagentix/) is one implementation in progress.

:::note[Status]
AWP is a draft. The current API version is `v1alpha1`; fields and semantics may change before `v1beta1`. See [Versioning](/specification/versioning/).
:::

## How AWP relates to MCP and A2A

AWP does not replace the Model Context Protocol (MCP) or the Agent2Agent protocol (A2A). It sits above them: a manifest references MCP servers as tool sources and A2A endpoints as remote agents.

|  | MCP | A2A | AWP |
| --- | --- | --- | --- |
| **Scope** | Agents ↔ tools and resources | Agent ↔ agent communication | Definition, governance, execution and audit of workflows |
| **Question answered** | How does an agent call this tool? | How do two agents talk to each other? | What may this workflow do, who owns it and what happened? |
| **Example artifact** | Tool and resource definitions | Agent card, task messages | Workflow, Agent and Policy manifests, audit events |

## What can AWP enable?

- **Portable workflows.** One manifest describing agents, tools, steps, triggers and inputs that different runtimes can read.
- **Enforced boundaries.** Budgets, permissions, approvals and policies that a runtime applies before an action, with default deny.
- **Human decisions where they matter.** Approval gates for actions such as production deployment, with separation of duties.
- **Reproducible audit trails.** Standard audit events, decision traces and execution records for every run.
- **A trusted supply chain.** Secrets by reference, versioned and signed manifests, pinned images and dependency declarations.
